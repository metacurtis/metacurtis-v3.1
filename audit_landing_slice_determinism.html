8) Recommendations (Grounded)

R1. Collapse stage/progress writes to one authority

What to change: Remove stage/progress mutation from narrativeAtom (jumpToStage/setStage/setGlobalProgress/setScrollProgress) and make it read-only/derived from stage authority.

Why: Restores single-writer invariant for narrative time and stage state.

Evidence: stageAtom.js:376-501 and narrativeAtom.js:69-175 both mutate overlapping fields.

Expected outcome: Deterministic stage/progress with no atom drift.

Risk / rollback: Medium. Keep compatibility shim (useNarrativeStore) for one release; rollback by re-enabling adapter-only methods.

R2. Single scroll binding contract

What to change: Keep one production scroll listener (recommended: ScrollOrchestrator), remove ConsciousnessTheater production scroll binding at :734.

Why: Eliminates race between two progress writers.

Evidence: ScrollOrchestrator.js:78, ConsciousnessTheater.jsx:734, TheaterDirector.js:2132.

Expected outcome: Stable stage progression and consistent fragment triggers.

Risk / rollback: Medium. If UX regresses, temporarily gate old listener behind dev flag only.

R3. Canonical morph writer only

What to change: Route all morph updates through one emitter path (prefer MorphAnimationController), remove direct emitMorphProgress(... source:'demo') in Director/Engine.

Why: BeatBus enforces single source owner.

Evidence: bus/index.js:461-467, MorphAnimationController.js:37-41, TheaterDirector.js:549,567,620, ConsciousnessEngine.js:654.

Expected outcome: No blocked morph events; demo/form slice morph behaves consistently.

Risk / rollback: Medium-high. Validate demo timing snapshots before removing old emitters.

R4. Fix navigation contract mismatch

What to change: Replace window.StateCommands.setStage(...) path with canonical unifiedNav.navigateToStage(...) or implement explicit StateCommands.setStage contract.

Why: Current path points to missing method and silently falls to bypass fallback.

Evidence: NavigationCommands.js:38-43; StateCommands.js has no setStage method (no grep hits).

Expected outcome: Deterministic stage transitions, fewer hidden fallbacks.

Risk / rollback: Low-medium. Keep fallback behind explicit dev-only guard.

R5. Enforce renderer sink boundary

What to change: Remove direct window.narrativeAtom.activateMemoryFragment from renderer; emit intent event and let store/orchestrator handle activation.

Why: Renderer should not mutate narrative state.

Evidence: WebGLBackground.jsx:1809-1811.

Expected outcome: Cleaner authority separation and testable event flow.

Risk / rollback: Low. Keep current behavior behind temporary compatibility flag during transition.

R6. Remove legacy naming drift surfaces

What to change: Delete or update stale store paths and stage-name remnants (featureFlags.js, MemoryFragments.jsx).

Why: Reduces accidental invocation of dead architecture and stage-model mismatch.

Evidence: featureFlags.js:173,177; MemoryFragments.jsx:89-104.

Expected outcome: One canonical naming model for landing slices and store APIs.

Risk / rollback: Low. These paths appear unused; can restore from VCS if needed.

9) Proposed Refactor Plan (Minimal Steps First)

  1. Rename/merge store surfaces: treat stageAtom as canonical stage/progress authority; convert narrativeAtom to non-authoritative narrative metadata only.
  2. Define StageOrchestrator contract: explicit API for setScrollProgress -> derives stageIndex/stageProgress/currentStage once; no duplicate derivation elsewhere.
  3. Move scroll binding to one place: keep only orchestrator-bound scroll listener in production. Remove duplicate ConsciousnessTheater progression scroll effect.
